# AI Game Player Pitch · Blender 交付说明

工程规格：Blender 5.2.2 LTS；1920×1080；60 fps；16:9；7 分 40 秒（27,600 帧）。17 个镜头按原材料的 6 个主幻灯片章节组织，A 负责体验与产品，B 负责 AI 与工程，最后一镜 B 接 A。

## 文件

- `visuals.blend`：`MODEL_*` 是原创建模源场景；`S01_*` 至 `S17_*` 是可编辑的 Blender Video Sequencer 动画。标题、模块、路径、搜索树、卡片和关键帧均可编辑，统一使用 Inter 字体。可在 Scene 下拉菜单选择镜头。
- `edit.blend`：成片剪辑时间线；仅引用已经渲染的 MP4 和 PNG，不引用视觉场景进行逐帧重渲染。
- `rendered/shot_01.mp4` 至 `shot_17.mp4`：独立动画镜头，1080p60。`shot_XX_hold.png`：相同镜头的末帧，可作为任意长度静止段。
- `preview/AI_Game_Player_Pitch_no_voice.mp4`：完整无旁白、无人物预览，保留字幕初稿及少量原创轻音效。
- `assets/`：Blender 渲染的棋盘透明素材、隐藏人物框、嵌入字体、静音占位和原创轻音效。
- `shots.json`：镜头编号、原台词、讲述者、目标时长及帧位置；同样写入工程内部 Text 数据。
- `subtitles_draft.srt`：英文字幕初稿，按预计语速分段；需要按真实录音重新对齐。
- `qa/`：关键帧、工程及媒体核查记录、规则检查。过程日志仅用于排查。

整个 `AI_Game_Player_Pitch` 文件夹一起移动，保持内部目录不变。工程内素材均使用相对路径，字体另外打包进 `.blend`。原始 EoI 和分镜文件未修改。

## 旁白、人物与字幕替换

1. 打开 `edit.blend`，切到 Video Editing 工作区；若视图只显示时间线，在编辑器 View 菜单中选择 Sequencer & Preview。先另存一个工作副本。
2. 旁白通道 2、3 分别命名为 `旁白 A / VO_A`、`旁白 B / VO_B`。静音条只是时长占位。删除相应占位，使用 Add → Sound 导入真实录音，放到同镜头标记处并取消该通道静音。镜头 17 的预设交接在 7:25，之后按录音调整。
3. 人物通道 8、9 分别为 `人物 A / PERSON_A`、`人物 B / PERSON_B`，默认隐藏。删除对应 PNG 占位，Add → Movie 导入人物视频；将人物音轨删掉或静音，避免和旁白重复。16:9 人物素材缩放至 250×140；原始 1920×1080 视频的缩放值为 0.130208，位置偏移 X=730、Y=307。两人并排时 A 的 X=460，B 的 X=730。占位安排在右上角，避开棋盘、技术图形、页眉和字幕。
4. 通道 7 是可编辑 TEXT 字幕，默认可见。依照录音修改边界和文字；正式录制前必须补齐镜头 4 的真实团队技能。隐藏通道 7 可导出纯视觉版本。

可选的批量导入：在本文件夹新建 `recordings/`，使用 `S01_A.wav`、`S01_A.mp4`、`S02_B.wav` 等镜头命名；镜头 17 分别使用 `S17_B` 和 `S17_A`。在 Blender Text Editor 打开 `scripts/import_recordings.py` 并运行。仅替换找到对应录音/视频的占位，其余保留且隐藏；不会自动保存工程。30fps 等不同帧率的人物素材会由 Blender 在 `recordings/.blender_cache/` 内自动转换为 60fps，保持原速度，可能需要少量导出时间。若实际录制长度短于占位，会在控制台提示。导入后检查人物裁切、镜头 3 与 17 的双人位置及字幕同步。也可完全手工替换。

## 时间调整

- 每镜头包含 `SXX` 入点标记及 `hold / extend here` 标记，台词存在 `shots.json` 和 Scene 自定义属性中。
- 需要延长时，将 `rendered/shot_XX_hold.png` 放在该镜头末端、同一图形轨道上，拉长到所需长度，再将后续镜头、声音、字幕、人物条和时间线标记一起后移相同帧数。每秒 60 帧。末帧是渲染素材，不会触发场景重渲染。
- 需要缩短时优先裁掉可读信息揭示后的停留部分，不截断路径、MCTS 四步或关键标签的出现。实际旁白不必变速。
- 默认转场为 36 帧（0.6 秒）缓入缓出的叠化，使用上一镜末帧与下一镜头开头重叠；没有改变原 7:40 的镜头分工。改变镜头边界时一并移动该 `TRANSITION / extendable hold` 条，并检查透明度关键帧。
- 仅调整剪辑长度、人物、旁白和字幕时不必重渲染 `visuals.blend`。若改变图形内容，进入相应 `SXX` 场景，局部修改后只重渲染该镜头；输出到同名 MP4，重新打开剪辑工程或重载素材即可。
- 如需改变原创建模，修改对应 `MODEL_*` 场景并渲染覆盖 `assets/board_*.png`，再重渲染使用它的视觉镜头。不要运行 `build.py` 来保存手工修改，它是从头重建用的脚本。

## 导出

`edit.blend` 已配置：帧 1–27600、1920×1080、100%、60 fps、Video、FFmpeg、MPEG-4、H.264、High Quality、AAC 48 kHz。真实录音导入后取消对应声音通道静音，保留或隐藏人物和字幕通道，Render → Render Animation 即可。

Blender 5.2 的输出设置需要先选择 Media Type=Video、File Format=FFmpeg，再选 Container=MPEG-4；切换媒体类型可能重置容器。最终输出路径为 `//preview/AI_Game_Player_Pitch_no_voice.mp4`，正式导出时改名，避免覆盖交付预览。材料未提供课程规定的最终官方文件名，提交前按课程要求重命名。

## 内容和规则

开场由标准起始局面经过 H e1→e2、AI e9→e8 得到，轮到人类行动。移动分支 e2→e3 和放墙分支是独立的“假如”，不作为连续两步；墙库存分别为 10/10 与 9/10。路径指南绕开另一枚棋子，遵守格点邻接与墙阻挡，不代表实际对局结果。

规则模块中的红墙是明确标注的测试预览：现有 h(0,1)，拟放 v(1,0) 会封闭人类角落路径，因此被拒绝；随后展示有效墙及双方保留的路线。墙坐标为零起点，h 阻断纵向边，v 阻断横向边。路径、跳跃、斜跳例外、墙体交叉和重叠已做规则检查，记录见 `qa/rules_validation.json`。依据 Gigamic 官方规则：https://export.gigamic.com/wp-content/uploads/2021/01/INS-RULES-QUORIDOR_10-2016.pdf 。

搜索标注 `Illustrative search`，GUI 标注 `Proposed interface`，预算及计划标注 `Provisional`。未制作虚构的胜率、性能结果、运行演示或成员技能。镜头 4 的资料缺少已确认技能。画面仅展示提案中的通用工作领域，工程内保留待补齐旁白备注；该镜头的字幕占位默认单独隐藏，录制真实团队介绍后再替换。字幕按预计时长生成，不能当作已经与真实录音同步的字幕。
